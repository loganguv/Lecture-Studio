# Lecture Studio Support

## Get help

- Review the latest [release notes](https://github.com/loganguv/Lecture-Studio/releases).
- Search existing [GitHub issues](https://github.com/loganguv/Lecture-Studio/issues).
- If the problem is not already reported, open a new issue without attaching private recordings or transcripts.


```text
lecturestudio.support@gmail.com
```

## Include in a problem report

- Lecture Studio version and build
- macOS version
- Mac model or Apple chip
- What you expected
- What happened
- Steps that reproduce the problem
- Diagnostic text shown by Lecture Studio, after reviewing it for private paths or filenames

## Never post publicly

Do not post:

- recordings or transcripts containing private information;
- passwords, verification codes, API keys, signing keys, or certificates;
- Keychain exports;
- private student, instructor, medical, employment, or financial information.

## Common installation issue

Lecture Studio is independently distributed and is not currently notarized by Apple. If macOS blocks the first launch:

1. Try to open Lecture Studio once.
2. Open **System Settings → Privacy & Security**.
3. Scroll to Security and click **Open Anyway** for Lecture Studio.
4. Confirm the choice.

Do not disable Gatekeeper globally.

## Data location

Lecture Studio data is normally stored at:

```text
~/Library/Application Support/Lecture Studio/
```

Export important data before deleting or repairing this folder.
